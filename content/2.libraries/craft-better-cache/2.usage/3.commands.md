## `invalidate`

Applies the refresh strategy to every cached page. Use it after deploys.

::code-group

```bash [ddev]
ddev craft better-cache/cache/invalidate
```

```bash [php]
php craft better-cache/cache/invalidate
```
::

## `clear`

Deletes all cached pages, the tag index and, with a purger, the CDN cache.

::code-group

```bash [ddev]
ddev craft better-cache/cache/clear
```

```bash [php]
php craft better-cache/cache/clear
```
::

## `clear-url`

Clears a single absolute URL and, with a purger, purges it from the CDN. Fails if the URL belongs to no site.

::code-group

```bash [ddev]
ddev craft better-cache/cache/clear-url https://example.com/blog
```

```bash [php]
php craft better-cache/cache/clear-url https://example.com/blog
```
::

## `warm`

Queues a render of all live pages that match the included URI patterns, plus every page already in the tag index, including its query string variants.

::code-group

```bash [ddev]
ddev craft better-cache/cache/warm
```

```bash [php]
php craft better-cache/cache/warm
```
::

## `refresh-scheduled`

Updates pages whose entries reached their post or expiry date. Run it from cron, e.g. every minute.

::code-group

```bash [ddev]
ddev craft better-cache/cache/refresh-scheduled
```

```bash [php]
php craft better-cache/cache/refresh-scheduled
```
::

## `blitz/config`

Translates `config/blitz.php` into a Better Cache config. Blitz settings saved in the control panel are not read. Settings without a Better Cache counterpart are listed as comments at the top. See [Switching from Blitz](/libraries/craft-better-cache/usage/switching-from-blitz).

::code-group

```bash [ddev]
ddev craft better-cache/blitz/config > config/better-cache.php
```

```bash [php]
php craft better-cache/blitz/config > config/better-cache.php
```
::

::alert{variant=note}
  `php craft clear-caches/all` also clears all cached pages, the tag index and (with a purger) the CDN. In deploy scripts, prefer `better-cache/cache/invalidate`.
::

## Control Panel

Invalidate, warm and clear are also available under **Utilities** → **Better Cache**, together with the number of cached and stale pages per site. For users with access to that utility, the entry sidebar shows whether the entry's page is cached and can clear it.
