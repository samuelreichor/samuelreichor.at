## Control Panel

Admins can manage the settings in the control panel under **Settings** → **Plugins** → **Better Cache**.

## Config File

You can define a multi-environment aware config in `config/better-cache.php`. Settings in the config file override the control panel settings.

### `enabled`

Whether pages are cached, served and refreshed.

```php
return [
  '*' => [
    'enabled' => false, // default
  ],
];
```

::alert{variant=warning}
  With the web server snippets in place, the web server keeps serving stored files after you disable Better Cache. Run `php craft better-cache/cache/clear` before disabling it.
::

### `includedUriPatterns`

Regex patterns for URIs that get cached, keyed by site handle (`*` applies to all sites). URIs are matched without a leading slash. Nothing is cached by default.

```php
return [
  '*' => [
    'includedUriPatterns' => [
      '*' => ['.*'],
      'en' => ['^blog'],
    ],
  ],
];
```

### `excludedUriPatterns`

Regex patterns for URIs that are never cached, even if they match an included pattern.

```php
return [
  '*' => [
    'excludedUriPatterns' => [
      '*' => ['^account', '^search'],
    ],
  ],
];
```

### `refreshStrategy`

What happens to a cached page when its content changes.

- `clear`: Deletes the page. Nothing is re-rendered, the next visitor renders it through Craft and caches it again.
- `expire`: Marks the page as stale and queues a re-render. Visitors keep getting the stale page until the fresh one replaces it, so no request ever waits for Craft. Stale pages are sent without CDN headers.
- `refresh`: Deletes the page and queues a re-render right away. Until the queue job has run, visitors are served by Craft.

Re-renders run as queue jobs, see [Queue](#queue).

```php
return [
  '*' => [
    'refreshStrategy' => 'clear', // default
  ],
];
```

### `storageDriver`

Where cached pages are stored.

- `file`: HTML files in `cachePath`, which the web server can serve directly.
- `craftCache`: Craft's cache component (e.g. Redis). Pages are always served by PHP. `php craft clear-caches/data` also drops them.

```php
return [
  '*' => [
    'storageDriver' => 'file', // default
  ],
];
```

### `cachePath`

Directory for cached pages when using the `file` driver. Must not be the webroot, the project root, one of Craft's own directories or a parent of them. A directory inside them, like `@storage/better-cache`, is fine.

```php
return [
  '*' => [
    'cachePath' => '@webroot/cache/better-cache', // default
  ],
];
```

### `includedQueryParams`

Regex patterns for query param names, keyed by site handle. Each included param makes its own cached page, so `/events?category=5` and `/events?category=6` are cached separately.

```php
return [
  '*' => [
    'includedQueryParams' => [
      '*' => ['^(page|category)$'],
    ],
  ],
];
```

### `excludedQueryParams`

Query params that are ignored, so `/events?utm_source=newsletter` gets the page cached for `/events`.

```php
return [
  '*' => [
    'excludedQueryParams' => [
      '*' => ['gclid', 'fbclid', 'utm_.*'], // default
    ],
  ],
];
```

::alert{variant=note}
  A URL with a query param that is neither included nor excluded is not cached. That way a template that reads the param never puts its output into a page other visitors get.
::

### `warmConcurrency`

Number of pages rendered at the same time when warming or refreshing.

```php
return [
  '*' => [
    'warmConcurrency' => 3, // default
  ],
];
```

### `cdnMaxAge`

The `s-maxage` in seconds sent to the CDN. See [CDN](/libraries/craft-better-cache/usage/cdn).

```php
return [
  '*' => [
    'cdnMaxAge' => 31536000, // default
  ],
];
```

### `cacheTagHeader`

Name of the cache tag header. Use `Surrogate-Key` for Fastly, or an empty string to send no tag header.

```php
return [
  '*' => [
    'cacheTagHeader' => 'Cache-Tag', // default
  ],
];
```

### `purger`

Class name of a `PurgerInterface` implementation, `null` for no CDN.

```php
return [
  '*' => [
    'purger' => null, // default
  ],
];
```

## Queue

Invalidations and re-renders run as queue jobs on Craft's `queue` component. To keep them apart from other jobs, define a second queue in `config/app.php`, bootstrap it so it gets its console commands, and point Better Cache to it:

```php [config/app.php]
return [
  'bootstrap' => ['betterCacheQueue'],
  'components' => [
    'betterCacheQueue' => [
      'class' => craft\queue\Queue::class,
      'channel' => 'better-cache',
    ],
    'plugins' => [
      'pluginConfigs' => [
        'better-cache' => ['queue' => 'betterCacheQueue'],
      ],
    ],
  ],
];
```

Then run a worker for it with `php craft better-cache-queue/listen`. The command name follows the component ID.

## What Is Never Cached

Even on an included URI, Better Cache neither serves nor stores:

- Requests other than GET, action requests, preview and token requests, and URLs with `?no-cache=1`
- URLs longer than 2048 characters, `index.php` URLs and Craft's resource URLs
- Logged-in users with the debug toolbar enabled, and users without access while the system is offline
- Query strings with a param that is neither included nor excluded (see [`includedQueryParams`](#includedqueryparams))

Logged-in visitors are served cached pages and keep their cookies, but a page rendered for them is never stored. Better Cache also skips responses that are not successful or not HTML, and pages containing transform generation URLs or two-step verification fields.

When a re-render answers with a redirect or a 4xx status, the cached page is deleted. A 5xx error keeps it until the next try.
